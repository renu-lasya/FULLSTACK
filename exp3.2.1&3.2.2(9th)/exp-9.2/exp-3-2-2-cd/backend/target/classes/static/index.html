What is Continuous Deployment + Canary?

Continuous Deployment (CD) automatically deploys after tests pass. Canary release sends the new version to a small % of users first. If healthy → promote to 100%. If errors → rollback to stable.

Code → Test → Docker Image → Canary (20%) → Monitor → Promote / Rollback

CD Pipeline Stages

GitHub Actions – cd.yml

on: push to main
jobs:
  1. test          → mvn test
  2. docker-build  → docker build + tag :canary
  3. canary-deploy → release at 20% traffic
  4. promote       → manual full rollout

Dockerfile (containerization)

FROM eclipse-temurin:17-jdk-alpine AS build
WORKDIR /app
COPY backend/ …
RUN mvn -DskipTests package

FROM eclipse-temurin:17-jre-alpine
COPY --from=build /app/target/*.jar app.jar
EXPOSE 8080
ENTRYPOINT java -jar app.jar

Commands (if Docker is installed):

docker build -t renulasya/cd-canary-lab:1.0 .
docker run -p 8080:8080 renulasya/cd-canary-lab:1.0
# or:  docker compose up --build

Run without Docker (demo)

cd backend
mvn spring-boot:run
# open http://localhost:8080

With Docker (optional)

docker compose up --build

CI/CD on GitHub

  1. Push project to GitHub
  2. Actions → CD Pipeline – Canary Deploy
  3. Tests run → Docker image builds → Canary step logs
